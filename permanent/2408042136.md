# basics of cryptography

**Cryptography** is the practice of securing communication by obscuring its contents to those beyond the intended recipient.

The two primary types of cryptography - asymmetric and symmetric key cryptography - utilize encryption keys. In this context, an **encryption key** is a string of characters that, when applied with an encryption algorithm, scrambles and alters data in a seemingly random manner. Similar to a physical key, the data is sealed (encrypted) and can only be accessed when the correct key is used to unseal it (decrypted).[^1] [^2]

When a plaintext is encrypted by a key, a **ciphertext** is created.[^1]

## asymmetric encryption

**Asymmetric encryption** involves generating two keys: a private key and a public key. The public key is shared with others, while the private key must be kept confidential.[^2]

The terms "private" and "public" are used to differentiate the two keys but are otherwise arbitrary; either key can be used as the private or public key, as long as their roles are consistent. What matters is that the keys are mathematically related. It is not algorithmically feasible to derive one key from the other. The keys are designed so that data encrypted with the public key can only be decrypted with the private key, and vice versa. The same key cannot be used for both encryption and decryption.

An example of asymmetric encryption may be as follows:

```
1. Bob encrypts a plain text using a public key provided by Alice (plain text + public key = ciphertext) 
2. Bob sends the ciphertext to Alice
3. Alice receives the ciphertext and decrypts it using Alice's private key (ciphertext - private key = plain text)
```
## symmetric encryption

**Symmetric encryption** describes cryptography that uses a single, shared key for both encryption and decryption. If the *shared secret* becomes known to unauthorized individuals, a new key must be created to maintain confidentiality.[^2]

Symmetric encryption is analogous to a physical key used in everyday life. The same key is used to both lock (encrypt) and unlock (decrypt) the door (the encryption algorithm), securing the contents inside (the data as ciphertext).[^1]

## diffie-hellman key exchange

Symmetric keys can be used in conjunction with asymmetric keys. For example, Bob and Alice can use the **Diffie-Hellman key exchange** to generate a shared symmetric key without directly transmitting it. Each party selects a private key and computes a public key, which will be exchanged. Using their own private key and the other’s public key, they can each derive the same shared symmetric key.
